Company Financial Data

Data Sources

The primary dataset comes from the U.S. Securities and Exchange Commission (SEC) EDGAR system, accessed through the CompanyFacts API. This API fetches standardized XBRL financial-statement data for publicly traded companies and requires no API key. 40 large companies across eight sectors were selected to ensure diversity in size, industry, and capital structure.

Additional data sources like macroeconomic indicators and market data are introduced later on this page.

Data Collection & API

The SEC dataset provides the fundamental measures of performance: profitability, leverage, and balance-sheet composition. Python was used to connect to the API. The script performs the following steps:

  1. Fetch the official company ticker mapping from company_tickers.json.
  2. Select a list of 40 tickers spanning eight sectors.
  3. For each company, call the CompanyFacts endpoint:
    https://data.sec.gov/api/xbrl/companyfacts/CIK{cik}.json
  4. Extract key US-GAAP financial metrics from the latest 10-K filing.
  5. Compute derived ratios (ROA, ROE, Debt-to-Equity, Profit Margin).
  6. Save both raw and clean CSV files.

API endpoint example:
https://data.sec.gov/api/xbrl/companyfacts/CIK0000320193.json
(where 0000320193 is the CIK for Apple Inc.)

See the full Python code: code/company_financials.py

Data Preparation

The raw data—stored in company_financials_raw.csv—is exactly what the SEC API returned. It contains the foundational financial metrics for each company’s most recent fiscal year (10-K filing), but it also contains gaps: Microsoft’s Total Liabilities, Meta’s Long-Term Debt, and several other fields show NA. This is common in raw financial data, since companies do not always report every standardized US-GAAP tag, and they may structure debt differently. Sector classification and derived ratios are also absent at this stage.

The following cleaning and transformation steps were performed in Python:

  • Impute missing values using the sector median, ensuring completeness without discarding entire rows.
  • Convert all numeric columns to float.
  • Compute three key ratios used throughout the analysis:
    • ROA (Return on Assets) = Net Income ÷ Total Assets
    • ROE (Return on Equity) = Net Income ÷ Total Equity
    • Debt-to-Equity = Long-Term Debt ÷ Total Equity
  • Add a sector column derived from ticker (manual mapping).

The result is company_financials_clean.csv—a structured, complete dataset ready for analysis.

Market Data

Data Source & Collection

Market data was obtained from Yahoo Finance using the Python library yfinance. Daily OHLCV data was collected for the same 40 companies from 2023-01-01 to present, and the following five features were computed for each company:

  • Latest Price — most recent closing price in the sample period.
  • Avg Volume — mean daily trading volume (a liquidity proxy).
  • Total Return — cumulative percentage price change from the first to the last day.
  • Volatility — annualized standard deviation of daily returns (std × √252); higher values indicate higher risk.
  • Beta — sensitivity of the stock’s returns to the S&P 500. Beta > 1 means the stock moves more than the market; Beta < 1 means less.

The full Python script is available here: code/market_data.py.

The raw market data is stored in market_data_raw.csv. Each row represents one trading day with the standard OHLCV fields. Although the sample appears clean (no missing values), the raw data is far too granular for cross-company analysis. It is therefore summarized into company-level risk metrics, stored in market_data_clean.csv. Each row in the clean file represents one publicly traded company, with five market-derived features to be merged with the financial dataset.

Exploratory Data Analysis

Before modeling, exploratory data analysis (EDA) was used to answer a focused set of questions:

  • How are the key financial and market variables distributed?
  • Which sectors show the highest (and lowest) financial performance?
  • Is market risk (volatility, beta) associated with accounting performance (ROA, ROE)?
  • Which variables are strongly correlated with each other, and are any redundant?
  • Are there outliers or extreme values that could distort ML models?

The plots and tables below address each of these in turn.

Summary Statistics

The summary statistics reveal two consistent patterns: extreme skew and wide dispersion.

  • Revenue spans from $1.5 billion to $648 billion, with a mean ($97.6B) far above the median ($59.8B)—a clear sign of right-skew driven by Walmart ($648B) and Apple ($215B).
  • Net Income ranges from −$2.2 billion (a net loss) to $73.8 billion (Alphabet). The mean again exceeds the median, confirming skew.
  • Total Assets range from $12.8 billion to nearly $3.9 trillion (JPMorgan Chase), with a standard deviation of $808 billion—the widest spread in the dataset. This reflects the enormous differences in balance-sheet size across sectors, from banks to technology to consumer staples.

Distribution of ROA by Sector

Code 
fin %>%
  ggplot(aes(x = reorder(sector, ROA, FUN = median), y = ROA, fill = sector)) +
  geom_boxplot() +
  coord_flip() +
  labs(x = "Sector", y = "Return on Assets", title = "ROA Distribution by Sector") +
  theme_minimal() +
  theme(legend.position = "none")

This boxplot shows how ROA distributes across the eight sectors. Three patterns stand out.

Sector matters. Median ROA is highest in Technology and Healthcare, and lowest in Utilities and Energy. The difference reflects asset intensity: tech and healthcare firms rely more on intellectual property and less on heavy physical assets, whereas utilities and energy require massive capital investment in infrastructure.

Within-sector variation is large. The Technology sector alone spans a wide interquartile range—from Nvidia (ROA ≈ 0.267) to firms with much lower profitability. This shows sector alone does not fully explain performance.

Financials behave differently. Banks like JPMorgan and Bank of America sit at low ROA (median ≈ 0.013–0.015), because their asset bases are enormous relative to profits. ROA is simply not the primary performance metric for banks.

In short, ROA is strongly associated with sector, but the within-sector spread suggests other factors like leverage, efficiency, market conditions are at play.

fin %>%

  scale_x_continuous(trans = signed_sqrt, labels = dollar_format(scale = 1e-9, suffix = "B")) +
  scale_y_continuous(trans = signed_sqrt, labels = dollar_format(scale = 1e-9, suffix = "B")) +
  labs(x = "Revenue (Signed Sqrt Scale, Billions)", y = "Net Income (Signed Sqrt Scale, Billions)", title = "Revenue vs. Net Income") +
  theme_minimal()

This scatterplot shows the relationship between Revenue and Net Income for all 40 companies, colored by sector. Because both variables are highly skewed and include negative values, a signed square root transformation compresses large values while preserving the sign.

Higher revenue generally corresponds to higher net income, but the relationship is far from tight, and the scatter tells the real story. Consider two firms at opposite ends of the spectrum:

  • Walmart: Revenue ≈ $648B, Net Income ≈ $15.5B (Profit Margin ≈ 2.4%).
  • Nvidia: Revenue ≈ $60.9B, Net Income ≈ $29.8B (Profit Margin ≈ 48.9%).

Nvidia earns nearly twice Walmart’s net income on one-tenth of the revenue. Revenue size does not determine profitability. Business model and sector strongly shape how much of each revenue dollar survives to the bottom line. Technology and Healthcare firms cluster in the upper-middle region (high net income relative to revenue), while Energy and Utilities cluster lower.

While revenue is positively associated with net income, the wide dispersion justifies including profitability ratios (ROA, ROE, Profit Margin) as complementary performance measures.

This scatterplot relates annualized market volatility to Return on Assets, colored by sector. It directly addresses the guiding question: Does greater market volatility tend to be associated with differences in company financial performance?

The points are widely scattered and show no clear upward or downward trend. Volatility alone is a poor predictor of accounting profitability. Sector clustering is still visible with Technology firms at the lower-volatility, higher-ROA region, while Utilities and Financials sit in the lower-volatility, lower-ROA region. But this may simply reflect the fact that volatility and ROA both depend on sector.

Nvidia and Tesla stand out with volatility > 0.48 and beta > 2.0. Nvidia also has a high ROA (≈ 0.267), while Tesla’s is more modest (≈ 0.123). High market risk can accompany strong profitability, but it doesn’t guarantee it.

As with volatility, there is no strong monotonic relationship between market risk and ROA. Neither risk measure is a clean predictor of profitability on its own.

Correlation Matrix

Pairwise correlations reveal which features are strongly related and which may be redundant.

Code 
library(reshape2)
library(ggplot2)

corr_vars <- merged %>%
  select(Revenue, NetIncome, TotalAssets, ROA, ROE,
         Debt_to_Equity, Profit_Margin, volatility, beta, total_return)

corr_mat <- cor(corr_vars, use = "complete.obs")
melted <- melt(corr_mat)

ggplot(melted, aes(x = Var1, y = Var2, fill = value)) +
  geom_tile(color = "white") +
  geom_text(aes(label = round(value, 2)), size = 3) +
  scale_fill_gradient2(low = "firebrick", mid = "white", high = "steelblue",
                       midpoint = 0, limits = c(-1, 1)) +
  labs(title = "Correlation Matrix", x = NULL, y = NULL) +
  theme_minimal() +
  theme(axis.text.x = element_text(angle = 45, hjust = 1))

Four patterns emerge:

  • Size variables cluster tightly. Revenue, Net Income, and Total Assets are strongly positively correlated: larger firms are larger on every dimension. This creates multicollinearity, which matters for linear models.
  • Profitability ratios cluster moderately. ROA, ROE, and Profit Margin are positively correlated with each other, but not perfectly. This shows that each captures a slightly different aspect of profitability.
  • Leverage behaves independently. Debt-to-Equity shows a weak or negative relationship with profitability measures, echoing the AbbVie outlier effect.
  • Risk measures are redundant. Volatility and Beta are strongly correlated with each other (both measure market risk), so including both in a model may not add explanatory power. Total Return is also positively correlated with volatility and beta, consistent with the classic risk-return relationship.

Insights for Models

The EDA reveals three concrete implications for the modeling phase:

  • Transform skewed variables. Revenue, Total Assets, and Net Income are heavily right-skewed and will need a log or signed-square-root transformation before use in linear models.
  • Standardize ratio variables. ROE and Debt-to-Equity contain extreme values that could dominate distance-based methods (KNN, SVM) unless standardized.
  • Reduce redundancy. Revenue, Net Income, and Total Assets carry overlapping information; volatility and beta carry overlapping information. Feature selection or dimensionality reduction will be needed before modeling.
  • Treat sector as a grouping variable. Nearly every plot shows sector-level structure. Whether through one-hot encoding, or stratified analysis, sector must be explicitly accounted for.

These data preparation and EDA set the stage for the modeling pages that follow.

- **Walmart**: Revenue ≈ $648B, Net Income ≈ $15.5B (**Profit Margin ≈ 2.4%**).
- **Nvidia**: Revenue ≈ $60.9B, Net Income ≈ $29.8B (**Profit Margin ≈ 48.9%**).

Nvidia earns nearly twice Walmart's net income on one-tenth of the revenue. **Revenue size does not determine profitability.** Business model and sector strongly shape how much of each revenue dollar survives to the bottom line. Technology and Healthcare firms cluster in the upper-middle region (high net income relative to revenue), while Energy and Utilities cluster lower.

While revenue is positively associated with net income, the wide dispersion justifies including **profitability ratios** (ROA, ROE, Profit Margin) as complementary performance measures.

### Correlation Matrix

Pairwise correlations reveal which features are strongly related and which may be redundant.

```{r}
#| label: corr-matrix
#| fig-cap: "Correlation Matrix of Financial and Market Variables"
#| fig-width: 9
#| fig-height: 7
library(reshape2)
library(ggplot2)

corr_vars <- merged %>%
  select(Revenue, NetIncome, TotalAssets, ROA, ROE,
         Debt_to_Equity, Profit_Margin, volatility, beta, total_return)

corr_mat <- cor(corr_vars, use = "complete.obs")
melted <- melt(corr_mat)

ggplot(melted, aes(x = Var1, y = Var2, fill = value)) +
  geom_tile(color = "white") +
  geom_text(aes(label = round(value, 2)), size = 3) +
  scale_fill_gradient2(low = "firebrick", mid = "white", high = "steelblue",
                       midpoint = 0, limits = c(-1, 1)) +
  labs(title = "Correlation Matrix", x = NULL, y = NULL) +
  theme_minimal() +
  theme(axis.text.x = element_text(angle = 45, hjust = 1))
```

Four patterns emerge:

- **Size variables cluster tightly.** Revenue, Net Income, and Total Assets are strongly positively correlated:
larger firms are larger on every dimension. This creates **multicollinearity**, which matters for linear models.
- **Profitability ratios cluster moderately.** ROA, ROE, and Profit Margin are positively correlated with each other,
but not perfectly. This shows that each captures a slightly different aspect of profitability.
- **Leverage behaves independently.** Debt-to-Equity shows a weak or negative relationship with profitability measures, echoing the AbbVie outlier effect.
- **Risk measures are redundant.** Volatility and Beta are strongly correlated with each other (both measure market risk), so including both in a model may not add explanatory power.
Total Return is also positively correlated with volatility and beta, consistent with the classic risk-return relationship.

# Insights for Models

The EDA reveals three concrete implications for the modeling phase:

- **Transform skewed variables.** Revenue, Total Assets, and Net Income are heavily right-skewed and will need a log or signed-square-root transformation before use in linear models.
- **Standardize ratio variables.** ROE and Debt-to-Equity contain extreme values that could dominate distance-based methods (KNN, SVM) unless standardized.
- **Reduce redundancy.** Revenue, Net Income, and Total Assets carry overlapping information; volatility and beta carry overlapping information. Feature selection or dimensionality reduction will be needed before modeling.
- **Treat sector as a grouping variable.** Nearly every plot shows sector-level structure. Whether through one-hot encoding, or stratified analysis, sector must be explicitly accounted for.

These data preparation and EDA set the stage for the modeling pages that follow.
